## 按编号读取本地巡检样例：已验收

目标：把请求中的 record_id 用于选择已存在的 synthetic JSON 文件，让分析路由取得后续模型分析所需的事实。

由学习者新建 ./app/records.py，实现 load_record(record_id:int)：

1. 使用 pathlib.Path，基于当前 records.py 的 __file__ 计算项目根目录，而不依赖启动终端的当前目录。
2. 数据目录为项目根目录下的 data/fixtures，文件名按 record_{record_id}.json 构造。
3. 使用 UTF-8 打开文件，使用 json.load 解析并 return 字典；记录不存在时保留 FileNotFoundError，让路由层处理。
4. 在 app/main.py 导入该函数，用 request.record_id 调用；当前阶段先 return 读到的原始学习记录，后续再将其交给模型生成分析输出。
5. 路由捕获 FileNotFoundError，raise HTTPException(status_code=404, detail="巡检记录不存在")，由 FastAPI 返回缺失记录响应。

目录定位提示：Path(__file__).resolve().parent 对应 app 目录，再取一次 parent 对应 envcheck-agent 项目根目录；Path 对象用 / 拼接子目录或文件名。

| 请求 | 预期 |
| --- | --- |
| record_id=1001 | HTTP 200，返回对应样例，check_status=completed、overall_result=fail |
| record_id=1003 | HTTP 200，返回对应样例，check_status=failed、overall_result=error |

| record_id="abc" | HTTP 422，请求体仍由 FastAPI 校验 |

HTTP 200 表示本轮成功读取并返回记录；记录中 fail/error 表示被记录的巡检业务结果，两者分别理解。当前阶段要求返回 synthetic 原始记录，不计为模型分析已接入。

## async/await 的顺序等待实验：已验收

为后续异步模型调用准备概念。先使用本地模拟等待，不访问模型 API；顺序版本验收后，再安排并发版本对照。

学习者新建 ./async_demo.py，依次完成：

1. 导入 asyncio 和 time。
2. 定义 async def mock_model(name)，打印当前名称开始，await asyncio.sleep(1)，再打印当前名称结束，最后 return 名称。
3. 定义 async def main()，用 time.perf_counter() 记录起点，依次 await mock_model("A")、await mock_model("B")、await mock_model("C")，计算并打印三个调用的总耗时。
4. 在脚本入口使用 asyncio.run(main()) 启动并运行。

概念约定：async def 定义协程函数；单独调用会产生协程对象；在另一协程中 await 或从同步脚本入口使用 asyncio.run 可推进运行。本实验的 await asyncio.sleep(1) 会暂停当前任务，事件循环可以在此期间运行其他就绪任务；连续 await 三个尚未调度的协程仍按顺序完成。

验收参考：打印顺序为 A 开始、A 结束、B 开始、B 结束、C 开始、C 结束，总耗时约 3 秒，允许调度误差。学习者提交实际打印与耗时，能说明 async def 不会自动把这三次调用变为并发。

    A 结束
    B 开始
    B 结束

## asyncio.gather 的并发等待与结果收集：已验收

解释：调用 mock_model 得到协程对象，gather 负责将这些协程调度为任务；本实验各任务在 asyncio.sleep 处挂起，等待时间可以重叠。外层 await 等待整组调用完成，并收集其返回值。

### 学习者追问：是否存在数据竞争

针对当前代码：三个调用读取各自传入的字符串，未共同修改可变业务对象；main 在 gather 完成后取得结果列表，因此无此类共享状态竞态。打印交错反映任务调度，不表示业务数据被破坏。

机制边界：同一个事件循环在其线程中使用协作式调度，一次执行一个任务；本实验的 asyncio.sleep 会挂起当前任务。单线程协程仍可能在挂起前后发生逻辑竞态，不能推导出所有异步代码天然安全。

导师在独立内存实验中让 A、B 共享 count=0 的字典，分别读取旧值、await asyncio.sleep(0)、将旧值加一写回。实测事件顺序：

    A reads 0
    B reads 0
    A writes 1
    B writes 1
    expected: 2; actual: 1

这是读改写跨挂起点导致的丢失更新。当前应用实验无此操作，无需为它添加锁；后续确有共享状态互斥需求时，在同一事件循环内使用 asyncio.Lock 保护必要的临界区，或由一个位置集中汇总独立返回值。该示例未写入学习者应用文件。

## 当前闭卷复盘

### 第一题：await 与执行顺序

问题：为什么不能把 text = await analyze_record(record) 改为 text = analyze_record(record)？去掉 await 后，text 得到的是什么？

学习者最初回答“需要在上一个代码执行完后才能执行这个，不加 await 可能报错”。导师纠正：await 等待当前这次异步调用完成并取得返回值；单独调用 async def 函数会创建协程对象，不会直接得到模型文本，传入后续 JSON 校验会因类型不符而失败。模型网络等待期间，事件循环可运行其他就绪任务。

随后展示连续两次 await analyze_record(...)，学习者正确回答“顺序”。顺序与并发的判断通过；协程对象的概念已讲解，尚未取得学习者对该概念的独立复述，不将其写成完全独立掌握。

### 第二题：结构校验与业务正确性

给定实际内核 118、期望 119、原记录整体 fail，而模型返回 completed/pass、failed_items=[]、root_cause=null。学习者回答：“能通过校验，但是不能认为分析正确，因为记录是没有通过的。”

判断通过：当前模型允许这些状态取值及字段类型，Pydantic 的结构校验不等于输出与原始记录的事实一致性校验。当前项目尚未实现自动业务一致性校验，不把口头判断记为该能力已实现。

### 最后一题：巡检错误与本次分析请求的错误

给定旧巡检记录 1003 因 SSH 连接超时而标记 failed/error；本次分析接口读取记录成功、模型正常响应、输出校验通过。询问本次 HTTP 应返回 200 还是 504，以及原因。
