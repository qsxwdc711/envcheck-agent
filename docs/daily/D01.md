## 固定 JSON 输出与程序解析：单个样例已验证

学习者修改 system 消息，将原来的“一到两句中文”要求替换为 JSON 输出约定，避免两种格式要求同时存在。只返回 JSON 对象，不附加 Markdown 代码围栏和前后说明。

字段约定：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| check_status | 字符串 | 保留输入的任务执行状态 |
| overall_result | 字符串 | 保留输入的业务巡检结果 |
| failed_items | 字符串列表 | 已明确未通过的检查项名称 |
| root_cause | 字符串或 null | 只有输入提供了可靠根因证据时才填写，否则为 null |

学习者取得回答文本后，使用 json.loads 转换为 Python 对象，并输出对象类型、failed_items 和 root_cause 进行核对。JSON 中 null 对应 Python 的 None。解析成功只证明 JSON 语法合法，字段、类型和事实还需要继续检查。

当前样例验收：两个状态保留为 completed 和 fail；failed_items 只有 kernel_version；root_cause 为 None。以上是单一样例的参考，不能推广为所有输入的固定答案。

学习者提交的实际终端输出：

    <class 'dict'> ['kernel_version'] None
    {"check_status":"completed","overall_result":"fail","failed_items":["kernel_version"],"root_cause":null}

验收结论：当前样例的 JSON 解析、两个状态、失败项和未知根因均符合约定。尚未进行多次稳定性测量。
