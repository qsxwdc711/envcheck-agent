# 内部交付运维工具使用助手：当前业务范围

2026-10-24，学习者明确取消日志监控、Categraf、夜莺与飞书告警方向，将应用收敛为供示例业务资料内部交付运维团队使用的工具使用问答助手。第一版定位为 RAG 应用，围绕 getinfo、nic_link_check、aidoc_download 的本地文档与经核对的参数说明回答问题。

## 目标与使用方式

帮助不熟悉工具的同事判断该用哪个工具、运行前准备什么、如何选择参数、预期生成什么结果，以及文档已覆盖的常见问题如何检查。回答以可追溯的步骤、命令模板、参数解释和来源为主；缺少环境条件时给出分支或提出必要澄清，缺少资料时明确说明。

第一版提供使用指导，命令由员工自行核对并执行。自动登录服务器、安装系统、执行脚本、故障监控与提交工单均不在当前范围。后续工具调用、LangGraph、记忆、MCP 和 Skill 以实际需求为依据逐步学习，当前不作为上线前提。

## 本轮资料核对发现

1. getinfo 工具文档的常用参数部分写了 --expect，但 getinfo.py（原始业务文件未发布） 的当前本地正式参数名是 --expect-file；sop_json_to_md.py（原始业务文件未发布） 的正式参数是 --expect。使用指导优先给各脚本正式参数名；argparse 默认允许无歧义的选项前缀，不能仅凭 --expect 这一缩写判定采集命令必然失败。
2. 文档将 getinfo 的 --username 列为必需，本地 参数定义（原始业务文件未发布） 为可选；是否可省略仍依赖本机 SSH 配置或自动检测等条件，不能向用户承诺所有环境都可省略。
3. roce_switch_check.py（原始业务文件未发布） 同时支持 --switchlist 和 --switch-leaf-list，两者是别名，不应把文档里的不同写法判为参数错误。交换机列表内容是 hostname/sysname，而非管理 IP。
4. 文档部分命令含 Markdown 转义，例如 getinfo\\.py、\\-\\-hostfile；清洗时应还原展示层转义，同时保留 shell 续行和配置正则中的有效反斜杠，不采用全局删除反斜杠的方式。
5. aidoc_download.py 的本地用法定义（原始业务文件未发布） 包含 -os、-iso、-pack、-fm 等参数和依赖条件，可整理成有来源的参数补充说明；它不能替代尚缺的完整 QEMU 操作文档。仅阅读源码，没有执行下载、打包或安装。

上述结论以当前本地文件为准，未确认工具发布版本。清洗副本应保留原始来源，并将经核对的参数说明与原文区分；原材料不就地覆盖。涉及凭据的示例使用占位符。

## 知识库与回答约定

每个片段至少包含 chunk_id、tool_name、source、section、source_type、content，复用现有来源类型字段。tool_name 使用 getinfo、nic_link_check、aidoc_download 三个固定值。需要时再补网络类型、脚本名和版本字段；不能把 IB/RoCE 当成 nvidia/ascend 平台值。

按完整操作任务切分，尽量让适用条件、输入文件、命令和结果说明保留关联。先整理干净 Markdown 或经核对的参数说明，再向量化。推荐新集合 tool_usage_docs，与现有 envcheck_sop 分开验证，不覆盖原巡检数据。

回答沿用 answer、evidence_status、citations 三字段。依据本次检索片段回答；引用仅取本次实际支持内容的 chunk_id。未知项目配置、兼容版本和运行结果不得补编。文档与本地参数定义有差异时，说明适用文件或版本与核对依据。
